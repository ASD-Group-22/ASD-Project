Release 2 Request Flow

1 · Student 2 UI The browser submits the listing and request through the Student 2 backend API.
2 · Planner + Evidence The Planner creates a plan and the Student 2 adapter retrieves deterministic matching evidence through the owning backend.
3 · Worker + Reviewer The Worker uses only allowed evidence and the Reviewer checks the result against both the plan and evidence.
4 · Human Review Approve, correct, partially accept or reject the recommendation. The decision is persisted with the workflow history.
